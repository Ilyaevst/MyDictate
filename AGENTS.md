# MyDictate: инструкции для агентов

## Область и источники истины

- Эти правила действуют от корня репозитория. Перед работой проверяйте `git status --short` и сохраняйте пользовательские изменения.
- Каноническое поставляемое приложение находится в `swift/`: пакет `Parakey`, production-код в `swift/Sources/Parakey/main.swift`, metadata в `swift/Info.plist`; root scripts и CI собирают именно его как MyDictate.
- `NewMyDictate/` — изолированная экспериментальная нативная продуктовая оболочка с отдельными bundle ID и данными; рабочий движок диктовки к ней не подключён. Не переносите туда production-изменения без отдельной задачи.
- `ui-prototype/` — интерактивный веб-прототип интерфейса и дизайн-референс с отдельным вложенным Git root; это не приложение и не источник runtime-поведения. Для работы с ним соблюдайте его собственный самодостаточный `ui-prototype/AGENTS.md`: автоматическое наследование этого корневого файла при запуске задачи непосредственно из вложенного репозитория не предполагается.
- Текущие runtime-контракты, пути и команды подтверждаются кодом, `README.md`, `scripts/`, CI и соответствующим `Package.swift`.
- `PRIVACY.md`, `SECURITY.md` и `CONTRIBUTING.md` задают политику и контекст, но при расхождении с реализацией явно сообщайте о расхождении.
- Не восстанавливайте legacy-пути или названия по устаревшему документу и не исправляйте такой документ попутно, если это не входит в задачу.

## Платформа и продуктовые инварианты

- Production поддерживает только macOS 14+ на Apple Silicon (`arm64`, M1 или новее). AppKit, AVFoundation, CoreGraphics/TCC и macOS Accessibility — намеренные зависимости.
- Не обещайте и не добавляйте поддержку Intel, iOS, Linux или другого cross-platform runtime без отдельного решения и полного плана зависимостей.
- Распознавание аудио и обработка текста остаются локальными. Сеть допустима только для выбранных моделей и публичного GitHub release/update flow, описанных в `PRIVACY.md`.
- Не добавляйте аккаунты, рекламу, аналитику, телеметрию или выгрузку аудио/текста. Не пишите транскрипты, аудио, credentials или чувствительные полные пути в логи, diagnostics, issues или внешние сервисы.
- Запрашивайте только необходимые Microphone, Accessibility и Input Monitoring permissions; не обходите TCC и Gatekeeper.

## Hotkeys и keyboard-first

- Сохраняйте пять разных действий: обычное завершение, завершение с Enter, только clipboard, полная отмена и pause/resume.
- Глобальный event tap подавляет только точные назначенные события; несвязанные клавиши и системные/app shortcuts должны проходить. `Escape` не назначается и не управляет диктовкой.
- Все пять сочетаний должны отличаться. Одиночный modifier не может быть префиксом другого сочетания; исключение — pause modifier, где полный chord имеет приоритет над одиночным отпусканием.
- Изменение hotkey требует проверки press/release, hold/toggle, single/double press, auto-repeat, modifier order, отмены, pause и отсутствия перехвата обычных сочетаний.
- Основные сценарии должны работать без мыши. Сохраняйте предсказуемый focus order, Return/Escape semantics, видимый focus и содержательные VoiceOver labels; состояние не должно передаваться одним цветом.

## Audio lifecycle и сохранность результата

- До запуска capture должны быть готовы runtime, permissions и content storage; recovery journal создаётся до старта audio engine.
- Pause прекращает приём новых frames, но не завершает session, не очищает samples и не закрывает journal. Resume продолжает ту же запись без искусственной тишины; timer, mute и HUD остаются согласованными.
- При завершении сначала flush journal и сохраняйте source WAV, затем распознавайте локально. Транскрипт сохраняется до history, clipboard и попытки вставки.
- Recovery journal удаляется только после безопасного сохранения требуемых аудио- и текстовых артефактов; при ошибке распознавания или доставки сохраняйте данные для восстановления.
- Явная полная отмена — отдельная семантика: удалить in-flight journal/архив текущей операции и не создавать transcript, history или clipboard result. Sleep, termination и потеря route/permission используют recovery, а не эту отмену.
- Не допускайте гонок audio callback с pause/stop/engine reset и не переносите render-thread state на `@MainActor` без доказанной безопасной замены.

## Настройки, миграции и совместимость

- UserDefaults keys, bundle ID, каталоги, форматы archive/journal/corrections и update manifest — совместимый persistent API. Не переименовывайте и не удаляйте их без явной миграции.
- Новая настройка получает стабильный default и backward-compatible decoding. Повреждённые или legacy values должны безопасно нормализоваться, а не приводить к потере остальных настроек.
- Миграции данных сначала копируют и побайтно проверяют всё содержимое; при конфликте останавливаются. Старый источник можно переместить в Trash только после полной проверки.
- Обновления обязаны сохранять настройки, историю, аудио и модели. Не сбрасывайте permissions или пользовательские данные как побочный эффект.

## Проверка

- Проверки должны быть пропорциональны изменению. Для instruction-only и documentation-only задач не запускайте Swift-сборку и regression suite: достаточно проверки diff/whitespace и релевантных ссылок. Для изменения кода сначала запускайте ближайший targeted self-test. `./scripts/check.sh`, полный `--self-test all` и release-компиляция нужны для затронутого общего контракта, рискованного runtime-кода или подготовки релиза.
- Выполняйте команды из корня на поддерживаемом Mac. Базовая проверка: `./scripts/check.sh`.
- Hotkey: `swift run -c debug --package-path swift Parakey --self-test hotkey`.
- Audio/recovery: `swift run -c debug --package-path swift Parakey --self-test recording-lifecycle`; storage/migration: тот же вызов с `content-storage`.
- Полный regression suite: `swift run -c debug --package-path swift Parakey --self-test all`.
- Production-компиляция без app packaging/signing: `swift build -c release --package-path swift`.
- Только для явно заданной экспериментальной области: `swift test --package-path NewMyDictate`; для веб-прототипа: `npm --prefix ui-prototype test`.

## Дисциплина изменений

- Делайте минимальное целостное изменение с одним видимым результатом на задачу; не добавляйте несвязанные рефакторинги, форматирование, зависимости или «заодно» исправления.
- Запрос на анализ, аудит, review или отчёт без запроса реализации не меняет файлы.
- Основной агент самостоятельно выполняет обычные и локальные задачи; субагенты по умолчанию не создаются.
- Для большого неизвестного участка разрешён один ограниченный read-only scout, а после завершённой рискованной реализации — один независимый read-only reviewer. Перед созданием объясните конкретную пользу.
- Каждому дочернему агенту передавайте узкую задачу, релевантные пути, формат результата и условие остановки. Используйте `fork_turns="none"` по умолчанию; `fork_turns="all"`, более двух субагентов и вложенная делегация требуют отдельного разрешения владельца.
- Coding-субагент допустим только для действительно независимого модуля с непересекающимся набором файлов и конкретным результатом.
- Без отдельного явного разрешения не запускайте app packaging с `codesign`, signing/notarization, install/uninstall или `scripts/prepare-github-release.sh`.
- Без отдельного явного разрешения не меняйте версии и `update.json`/release feed, не создавайте commit/tag/release, не push/publish и не выполняйте destructive действия над Git, сборками, установленным приложением или пользовательскими данными.
